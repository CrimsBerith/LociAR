## 1. Core User Journey Matrix

| Journey ID | Title | Primary Persona | Pre-conditions | Primary Happy Path | Negative / Edge Case Paths | Acceptance Criteria | Test Target |
|---|---|---|---|---|---|---|---|
| **AJ01** | First Launch & Onboarding | New User | Fresh app install, network connected | 1. App launches with localized welcoming copy.<br>2. Language defaults to device locale or English fallback.<br>3. Auth view presented with terms/privacy consent links.<br>4. User accepts terms and initiates sign-in. | 1. No internet connection: displays retryable connectivity banner.<br>2. User taps terms/privacy before sign-in: in-app Safari sheet loads HTTPS policy without crash.<br>3. Missing permissions: camera/location explanation prompt displayed. | - No raw Turkish strings when device locale is English.<br>- Privacy policy and Terms URLs load valid HTTPS endpoints.<br>- Cannot bypass auth into private features. | `EnglishSmokeUITests/testSignedOutScreenIsEnglish`, `StoreReadinessTests/testStoreRequiredControlsArePresentInShippedUI` |
| **AJ02** | Authentication & Identity | Returning / New Member | App on Auth screen | 1. Taps "Sign in with Apple".<br>2. Apple sheet authorizes.<br>3. App receives credentials, exchanges for Firebase token, calls `ensureProfile`.<br>4. `luid` UUIDv5 custom claim derived and verified.<br>5. User transitions to main tab view. | 1. Apple Sign-in cancelled by user: returns cleanly to auth screen without crash.<br>2. Invalid or expired OTP code: inline error displayed, rate-limited attempts (5 max).<br>3. Legacy guest session: redirected to account linking view.<br>4. Disabled/suspended account: access rejected at server. | - Session persists securely in Keychain.<br>- Client never writes direct Firestore profile without callable.<br>- Handshake completes in < 3s under normal LTE/Wi-Fi. | `LociARTests/StoreReadinessTests`, `functions/test/auth.test.mjs` |
| **AJ03** | Map & Spatial Note Discovery | Active Member | Authenticated, location permission granted | 1. User opens Map tab.<br>2. Map queries `map_cells` around user coordinates.<br>3. Renders glass heat clusters and 6m pin groups.<br>4. Taps 6m group: sheet lists notes ranked by likes.<br>5. On-site user sees full decrypted note text. | 1. Remote user (outside note radius): note text is server-redacted, shows distance.<br>2. Location permission denied: shows clean educational prompt, falls back to default region without crash.<br>3. Heavy dense area: capped at 6m membership clusters to avoid UI freeze.<br>4. Rapid panning: debounced spatial queries to preserve quota. | - Zero unauthenticated reads of Firestore notes.<br>- Zooming never unlocks remote text.<br>- Cluster membership mathematically consistent within 6m. | `AuthGateUITests`, `LociARTests/ArchitectureAndPublishTests`, `functions/test/mapCells.test.mjs` |
| **AJ04** | AR Surface Post Creation | Verified Member | Camera and Location permissions granted | 1. User navigates to Create / AR.<br>2. ARKit detects horizontal/vertical surface.<br>3. Reticle indicates valid placement.<br>4. User enters text caption and/or selects a KLIPY GIF.<br>5. Taps Publish.<br>6. `createPost` validates the KLIPY slug and size, signs ARCore anchor token, returns active post.<br>7. Post appears floating in AR. | 1. User inputs external URL: rejected immediately with localized error.<br>2. User attempts adult content or banned phrases: rejected by server text check.<br>3. Rate limit reached (>10/hr or >50/day): cleanly blocked with cooldown message.<br>4. AR surface tracking lost during placement: reticle enters pending state, recovers smoothly.<br>5. Placement in protected zone: rejected unless admin zone exception provided. | - `createPost` is server-authoritative.<br>- GIF layers store the KLIPY provider, slug and dimensions only.<br>- Google sensor data disclosure visible on every AR view. | `AuthGateUserFlowUITests/testUserFlowCreateARPostAndViewIt`, `LociARTests/PinStateMachineTests` |
| **AJ05** | Location Note Authoring | Verified Member | On-site, GPS fix acquired | 1. User taps "Leave Note Here".<br>2. Device reads high-accuracy GPS fix.<br>3. User types note text, selects radius (15–100m).<br>4. User optionally adjusts pin position within 12m.<br>5. Taps publish: note published instantly with anonymous or attributed choice. | 1. User attempts to drag pin > 12m from measured fix: clamped/rejected by client and server validation.<br>2. Inaccurate GPS fix (>20m): user prompted to wait for satellite lock.<br>3. | **AJ06** | Social Interactions & Moderation | Active Member | Viewing post or note | 1. User likes note: counter incremented server-side.<br>2. User reports inappropriate post: callable logs report.<br>3. Post hits report threshold: automatically hidden from public queries within seconds.<br>4. User blocks an author: author's attributed posts or anonymous notes hidden for this user only. | 1. User attempts to like same post twice: idempotent, counter does not double-increment.<br>2. Muting anonymous author: hides their anonymous notes without revealing who the author is on other surfaces (differential privacy).<br>3. Offline state during like: optimistic UI with safe rollback on network failure. | - Counters written only by Cloud Functions / Admin SDK.<br>- Differential privacy test passes (`anonymous.test.mjs`).<br>- Flagged content hidden automatically. | `functions/test/integration/anonymous.test.mjs`, `admin/tests/policy.test.mjs` |
| **AJ07** | Account Deletion (App Store 5.1.1(v)) | Active Member | Profile Settings | 1. User navigates to Profile -> Settings -> Delete Account.<br>2. System displays permanent deletion warning.<br>3. User re-authenticates (Apple or email).<br>4. `deleteAccount` callable executed.<br>5. Apple Sign-in token revoked via Apple endpoint.<br>6. Firestore docs, Storage files, and Auth user permanently deleted.<br>7. Client Keychain wiped, user returned to Auth view. | 1. Network drop during deletion: atomic Cloud Function task retries until completed; partial deletion does not orphan data.<br>2. Apple token revocation failure: deletion aborts cleanly to maintain guideline compliance.<br>3. User cancels confirmation prompt: session remains intact. | - Hard deletion complete across Auth, Firestore, and Storage.<br>- Apple revocation token verified.<br>- App Store Review guideline 5.1.1(v) 100% compliant. | `functions/test/auth.test.mjs`, `LociARTests/StoreReadinessTests` |
| **AJ08** | Offline / Degraded Network | Any User | Low or no connectivity | 1. App launches with no network connection.<br>2. Displays non-blocking offline banner.<br>3. Shows cached map tiles and previously stored local notes.<br>4. When network reconnects, synchronizes state silently. | 1. Submitting post offline: cleanly informs user that live connection is required; does not hang or crash.<br>2. 500 / 429 server error: exponential backoff with human-readable error messages. | - No app hangs or unhandled Promise/Task errors.<br>- Transparent status messaging. | `LociARTests/ReliabilityTests` |
